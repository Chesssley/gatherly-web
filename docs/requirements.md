# 需求说明

最后更新时间：2026-06-04

本文按模块整理 Gatherly Web 当前项目需求。用户故事统一格式为：“作为 <角色>，我想要 <功能>，以便于 <价值>。”

## 首页活动流

| 项目 | 内容 |
|---|---|
| 模块目标 | 让游客和用户进入网站后能快速发现本地或同兴趣活动 |
| 用户故事 | 作为游客，我想要浏览首页活动卡片，以便于快速了解当前有哪些线下活动。 |
| 功能说明 | 首页展示活动卡片，包含标题、图片、城市、地点、时间、标签、人数和入口；支持搜索、标签、城市和日期等发现方式。 |
| 验收标准 | 首页可打开；至少能展示活动列表；活动卡片信息清晰；点击卡片进入详情页；移动端无明显错位。 |

## 注册登录

| 项目 | 内容 |
|---|---|
| 模块目标 | 建立用户身份，让用户可以报名、发布活动、加入圈子、发帖、评论、评分和私信 |
| 用户故事 | 作为游客，我想要注册并登录账号，以便于使用报名、发布和社区功能。 |
| 功能说明 | 支持注册、登录、退出、页面显示当前登录用户；当前代码还包含邮箱验证码、忘记密码、修改邮箱、修改密码和账号注销流程。 |
| 验收标准 | 注册页和登录页可打开；正确账号可登录；错误账号密码有提示；退出后清除登录状态；未登录访问受限功能会跳转登录或提示登录。 |

## 活动详情

| 项目 | 内容 |
|---|---|
| 模块目标 | 帮助用户在报名之前完整了解活动 |
| 用户故事 | 作为用户，我想要查看活动详情，以便于判断活动是否适合我参加。 |
| 功能说明 | 活动详情页展示标题、介绍、详情、时间、地点、城市、人数上限、当前参与状态、费用、标签、图片、准备事项、组织者、报名状态、评论和评分入口。 |
| 验收标准 | 从首页能进入活动详情；活动字段显示准确；报名按钮状态符合登录、满员、已报名、已过期、关闭等情况；页面在移动端可读。 |

## 活动发布

| 项目 | 内容 |
|---|---|
| 模块目标 | 让登录用户或可信组织者创建线下活动 |
| 用户故事 | 作为活动发布者，我想要发布线下活动，以便于邀请同好一起参加。 |
| 功能说明 | 登录用户填写标题、介绍、详情、时间、地点、人数上限、费用、兴趣标签、关联圈子、准备事项、时区和图片；发布后活动进入首页活动流。当前代码包含低信任分限制和官方/精选活动字段。 |
| 验收标准 | 未登录不能进入发布流程；必填字段校验有效；发布成功后跳转活动详情或首页；活动能在首页或搜索中出现；组织者自动成为活动参与者。 |

## 活动报名

| 项目 | 内容 |
|---|---|
| 模块目标 | 形成“发现活动 -> 查看详情 -> 报名参加”的核心闭环 |
| 用户故事 | 作为登录用户，我想要报名感兴趣的活动，以便于参加线下聚会。 |
| 功能说明 | 报名路由检查登录状态、活动状态、是否满员、是否已报名、是否过期，并创建 `Registration` 记录；支持取消报名。 |
| 验收标准 | 未登录用户报名会跳转登录；重复报名被阻止；满员活动不能报名；报名成功后人数更新；取消报名后状态更新；关闭或过期活动不能报名。 |

## 标签筛选

| 项目 | 内容 |
|---|---|
| 模块目标 | 让用户按兴趣快速缩小活动范围 |
| 用户故事 | 作为用户，我想要按兴趣标签筛选活动，以便于快速找到符合兴趣的内容。 |
| 功能说明 | 首页和搜索功能支持标签、关键字、城市、日期等筛选；活动和圈子均使用标签组织内容。 |
| 验收标准 | 标签入口可点击；筛选后展示相关活动；页面显示当前筛选条件；可以恢复查看全部活动。 |

## 同好圈

| 项目 | 内容 |
|---|---|
| 模块目标 | 让同兴趣用户在活动之外持续交流 |
| 用户故事 | 作为用户，我想要进入同好圈，以便于和相同兴趣的人交流经验。 |
| 功能说明 | 圈子列表展示圈子名称、标签、封面、简介、活跃程度和成员信息；详情页展示公告、成员、相关活动、帖子和评论。 |
| 验收标准 | 圈子列表和详情可打开；用户可加入或退出圈子；私密圈访问需要权限；圈子活跃信息展示清晰；管理员或圈主能管理部分圈子信息。 |

## 圈子帖子

| 项目 | 内容 |
|---|---|
| 模块目标 | 支持圈子内分享、讨论和临时约伴 |
| 用户故事 | 作为圈子成员，我想要发布帖子和评论，以便于分享经验或发起讨论。 |
| 功能说明 | 用户可在圈子内发帖，支持标题、内容、类型、图片；支持评论、楼中楼回复、评论图片、点赞、收藏、分享和删除。 |
| 验收标准 | 登录用户可发帖；未登录用户被提示登录；帖子和评论展示正常；图片上传后可展示；用户不能删除他人内容；管理员能治理违规内容。 |

## 评分与信任机制

| 项目 | 内容 |
|---|---|
| 模块目标 | 给线下活动参与提供基本可信度参考 |
| 用户故事 | 作为参加者，我想要在活动结束后评分，以便于帮助其他用户判断活动质量。 |
| 功能说明 | 当前代码包含 `Review` 旧版单项评分、`ActivityReview` 活动多维评分、`CircleRating` 同好圈评分和 `TrustScoreLog` 信任分记录；评分应限制不符合条件的用户，避免重复评分。 |
| 验收标准 | 只有符合条件的参加者可以评分；同一用户对同一对象不能重复评分；评分保存后展示平均分或评价内容；低信任分限制发起活动逻辑可人工验证。 |
