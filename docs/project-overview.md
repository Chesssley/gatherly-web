# 项目概述

最后更新时间：2026-06-04

## 项目定位

Gatherly Web / 聚场是一个面向小众兴趣爱好者的线下活动聚合与同好连接网站。项目重点解决的问题是：用户想参加复古相机、城市骑行、手冲咖啡、独立出版、桌游、阅读、音乐、轻户外等线下活动，但很难快速找到本地活动、同好圈子和可信参与者。

Gatherly 不是复杂算法推荐平台。当前代码更接近一个轻量社区型活动发现系统：通过活动时间、城市、地点、兴趣标签、搜索、评分、报名状态和信任分等简单规则，帮助用户发现本地或同兴趣活动。

## 用户痛点

- 小众兴趣活动信息分散，用户不知道去哪找。
- 线下活动需要提前判断时间、地点、人数、费用和准备事项。
- 新用户参加线下活动时缺少同好关系和信任参考。
- 活动组织者缺少低成本发布和管理小规模活动的工具。
- 同兴趣用户需要一个轻量空间发帖、评论、加入圈子和继续交流。

## 目标用户

| 用户类型 | 典型需求 |
|---|---|
| 游客 | 浏览活动、查看活动详情、了解平台内容 |
| 注册用户 | 报名活动、收藏活动、加入圈子、评论、发帖、私信 |
| 活动发布者 | 创建活动、设置人数上限、管理报名和活动状态 |
| 圈子成员 | 加入同好圈、发布帖子、评论回复、互动 |
| 管理员 | 管理用户、活动、圈子、帖子、评论、商家认证和操作日志 |
| 商家或组织者 | 申请商家认证，发布更可信的活动 |

## 核心价值

1. 降低活动发现成本：通过首页活动流、标签筛选、搜索和城市信息让用户快速找到活动。
2. 降低参与决策成本：活动详情集中展示时间、地点、人数、费用、准备事项和报名状态。
3. 建立轻量同好关系：用户可以加入圈子、发帖、评论、关注、私信和查看个人主页。
4. 增强线下信任：活动评分、用户互评、信任分和管理员治理帮助降低风险。
5. 支持课程协作交付：仓库包含 README、需求、Backlog、ER 图、测试报告、会议记录和协作规范。

## 核心功能模块

### 首页活动流

首页通过卡片展示活动图片、标题、日期、城市、地点、标签和参与信息。用户可以通过标签、时间、城市、关键字等方式发现活动。

### 注册登录

用户可以注册、登录、退出，并在页面上看到当前登录状态。代码中还包含邮箱验证码、密码修改、邮箱修改、忘记密码和账号注销相关路由。

### 活动详情与报名

活动详情页展示完整活动信息。报名逻辑包含登录检查、重复报名检查、人数上限检查、活动过期或关闭状态检查，并支持取消报名。

### 活动发布

登录用户可以发布活动。活动字段包括标题、简介、详情、城市、地点、开始与结束时间、时区、人数上限、费用、标签、关联圈子、准备事项和图片。当前代码还包含低信任分用户发布限制、官方活动标记和精选活动相关字段。

### 兴趣标签筛选

活动和圈子使用标签进行组织。首页和搜索路由支持按标签或关键字筛选，让用户用低成本找到对应兴趣内容。

### 同好圈与帖子

同好圈支持列表、详情、创建、加入、退出、权限请求、公告、封面、置顶帖子、成员角色、发帖、评论、楼中楼回复、图片和互动。

### 评分与信任机制

当前代码包含三类评价或评分结构：

- `Review`：旧版活动评分，包含单一 `rating` 和 `comment`。
- `ActivityReview`：活动多维评分，包含组织、场地、内容、价值、体验等维度。
- `UserReview`：参与者互评，包含准时、友善、沟通、可靠、尊重、安全等维度。

`TrustScoreLog` 记录用户信任分变化，配合用户 `trust_score` 字段支持基本信任机制。

## 产品特点

- 移动端优先：CSS 中包含大量响应式规则，卡片、导航和表单都考虑窄屏。
- 真实图片：活动和圈子使用本地图片、上传图片或 Cloudflare R2 对象存储 URL，避免纯占位内容。
- 简洁卡片：活动卡片、圈子卡片和个人内容卡片以标题、时间、地点、标签和状态为主。
- 明确行动按钮：报名、发布、加入、发帖、关注、私信和后台操作都使用明显按钮。
- 轻量技术栈：Flask + Jinja2 + HTML/CSS/原生 JS，便于课程团队理解和维护。
