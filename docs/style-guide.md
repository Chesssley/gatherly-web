# 页面风格规范

本文档定义 Gatherly Web 的页面风格和前端协作规则。项目固定使用 Flask + Jinja2 + HTML/CSS/原生 JavaScript，不引入 Bootstrap、Vue、React 或其他前端框架。

## 技术边界

- 模板使用 Jinja2，文件放在 `app/templates/`。
- 样式使用原生 CSS，主要维护在 `app/static/css/style.css`。
- 交互使用原生 JavaScript，主要维护在 `app/static/js/main.js`。
- 不引入 Bootstrap、Tailwind、Vue、React、jQuery 等新的前端依赖。
- 不把业务逻辑写进前端脚本；核心校验仍由 Flask 后端处理。

## 总体风格

Gatherly 面向线下兴趣活动，页面应保持清晰、温和、可信。优先保证信息好读、按钮好找、路径清楚，不使用过度复杂的装饰。

## 颜色

- 背景使用柔和浅色，避免大面积刺眼纯白。
- 主色以绿色系为主，体现线下连接、社区和友好感。
- 强调色可少量使用暖橙色，用于提示、状态或关键按钮。
- 同一页面不要随意增加新的主色。
- 错误、成功、警告状态需要有清晰但克制的颜色区分。

## 字体与文字

- 全站使用统一字体设置，优先 `Microsoft YaHei`、`PingFang SC`、Arial、sans-serif。
- 标题简洁，正文写具体信息，不堆砌口号。
- 按钮文案使用动词，例如“浏览活动”“发布活动”“报名参加”。
- 页面文案不要遮挡主要信息，不使用过长的按钮文字。

## 布局

- 页面主体内容使用统一 `.container` 控制宽度。
- 主要内容区块使用统一间距，避免内容贴边。
- 卡片、表单、信息面板使用统一圆角、边框和阴影。
- 移动端必须保证内容自然换行，不出现横向滚动。
- 不嵌套过多卡片，避免页面显得复杂。

## 组件规则

| 组件 | 建议类名 | 说明 |
|---|---|---|
| 按钮 | `.button` | 用于主要操作 |
| 活动卡片 | `.activity-card` | 用于首页活动流 |
| 卡片内容 | `.card-body` | 用于卡片内部布局 |
| 标签 | `.tag` | 用于兴趣标签、分类和状态 |
| 表单容器 | `.form-card` | 用于登录、注册、发布活动 |
| 表单输入 | `.form-input` | 用于 input、select、textarea |
| 表单错误 | `.form-error` | 用于字段级错误提示 |
| Flash 消息 | `.flash-msg` | 用于成功或失败提示 |

## 页面要求

- 新增页面应继承 `base.html`，复用导航、Flash 消息和公共布局。
- 新增样式前先检查 `style.css` 是否已有可复用类名。
- 不在 HTML 中写大量内联样式。
- 修改公共样式前确认是否影响多个页面。
- 页面应在桌面和移动端都可读、可点、无遮挡。

## 表单规范

- 表单字段需要有清晰 label。
- 必填字段和错误信息由后端表单校验兜底。
- 注册、登录、发布活动等表单保持统一宽度、间距和按钮样式。
- Flash 消息只展示操作结果，不承载复杂说明。

## 协作要求

- 前端改动应说明影响的模板和 CSS 类。
- 不为单个页面随意新增一套完全不同的视觉风格。
- 需要新增组件时，优先抽象为可复用 class。
- 不因为样式问题修改数据库模型、路由结构或业务逻辑。
